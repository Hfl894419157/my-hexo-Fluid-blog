# AI 产品图批量生成流程

这套工作流主要用于你目前的工业产品项目：

**主图、详情页、应用场景图、产品结构图、安装示意图、局部修改图。**

它不是“输入一个产品名，一键生成几十张图”，而是建立一套：

> **资料标准化 → 产品真值锁定 → 批量策划 → 批量生成 → 自动检查 → PS精修 → 统一导出**

的完整生产系统。

---

## 一、工作流总体结构

```Plain
产品资料输入→AI读取并整理资料→建立产品真值档案→生成整套图片策划→拆分为单图任务→自动生成提示词→批量生成场景底图→产品主体合成与一致性控制→AI自查与人工审核→PS批量排版、替换、导出→项目归档与模板复用
```

---

## 二、第一阶段：产品资料输入

每个产品建立一个独立项目文件夹。

```Plain
GTS200_DS18B20
├─ 01_原始产品图
├─ 02_产品PDF
├─ 03_参数表
├─ 04_尺寸图
├─ 05_接线图
├─ 06_应用资料
├─ 07_竞品参考
├─ 08_品牌规范
└─ 09_输出要求
```

输入资料包括：

1. 产品多角度照片
2. 产品PDF说明书
3. 参数、尺寸、材质、接口信息
4. 探头、线缆、尾端、端子配置
5. 应用场景
6. 平台要求
7. 图片比例与数量
8. 字体、字号和颜色规范
9. 参考图片
10. 禁止修改的产品细节

这一步不能直接让AI出图。

---

## 三、第二阶段：建立“产品真值档案”

这是整套工作流最重要的部分。

AI先从产品图、PDF和参数资料中提取一个统一档案，后续所有图片、提示词和检查规则都必须调用这个档案。

### GTS200真值档案示例

```Plain
产品名称：
GTS200 DS18B20 Digital Temperature Sensor

产品类型：
可定制数字温度传感器，不是单一固定SKU

标准产品结构：
不锈钢圆柱探头
黑色PVC线缆
三芯裸线尾端

线芯颜色：
红色 = VDD+
黄色 = DATA
黑色 = GND

允许定制：
探头结构
探头尺寸
探头材质
线缆长度
线缆材质
连接器
尾端形式
安装方式

禁止错误：
不得改变探头真实比例
不得改变线芯数量
不得随机修改线芯颜色
不得增加不存在的端子
不得把传感器直接悬浮在设备外部
不得把内部安装产品错误展示在设备表面
不得混用不同型号结构
不得凭空生成错误螺纹
```

### 真值档案需要包含六类内容

- 产品身份：产品名称、型号、类别、核心用途。
- 外观真值：形状、颜色、比例、材质、接口、螺纹、探头、线缆、接头数量。
- 参数真值：量程、精度、输出、供电、协议、防护等级、工作温度。
- 应用真值：安装在什么设备、什么位置、如何工作。
- 可变内容：探头、线缆、端子、尺寸、材质、参数、包装。
- 禁止内容：产品不能出现的结构、场景、文案和技术错误。

## 四、第三阶段：生成整套图片策划

AI不能直接生成图片，而是先输出“图片任务清单”。

例如一个产品需要:

> ```
> 1、主图系统：
>
> - 产品定制能力首图
> - 多探头结构定制
> - 多尾端接口定制
> - 线缆材质定制
> - 核心技术卖点
> - 多场景应用
> - OEM/ODM能力
> - 包装与交付
> ```

> ```
> 2、详情页系统：
>
> 产品定位首屏
> 用户需求与解决方案
> 探头定制
> 线缆定制
> 连接器定制
> 产品性能
> 应用场景
> 选型与询盘
> ```

每一张图必须先定义：

```Plain
图片编号
图片类型
图片目标
核心信息
画面结构
产品组合
文案层级
背景方向
禁止事项
输出尺寸
对应提示词
自查规则
```

## 五、第四阶段：建立提示词变量系统

不要为每一张图片从头写提示词。

建立固定提示词框架，把需要变化的内容放进方括号。

### 通用变量

```Plain
[品牌名称]
[产品名称]
[产品型号]
[图片类型]
[图片目标]
[画面比例]
[产品组合]
[产品位置]
[场景环境]
[核心卖点]
[主标题]
[副标题]
[标签文案]
[视觉风格]
[背景方向]
[品牌色]
[字体]
[字号]
[禁止事项]
```

### 提示词由五层组成

- 第一层：产品真值：规定产品不能变形、不能改结构。
- 第二层：图片任务：这张图具体表达什么。
- 第三层：画面布局：产品、文案、场景分别放在哪里。
- 第四层：视觉设计：光线、空间、背景、质感、品牌色。
- 第五层：负面约束：禁止错误产品、错误线缆、错误接头、错误文案和错误场景。

---

## 六、第五阶段：图片生成方式

工业产品图不能完全依赖纯文字生成。

应采用“产品主体与场景分离”的方式。

### 推荐生成结构

```Plain
真实产品图
+
AI生成场景
+
产品主体合成
+
光影匹配
+
信息排版
```

### 具体分工

```
AI负责：场景背景、环境氛围、辅助元素、管道、设备、空间、光线、数据流、局部创意。

真实产品图负责：产品外形、接口、探头、线缆、端子、屏幕、按键和品牌信息。

PS负责：产品抠图、透视、阴影、反光、色彩匹配、排版、字体、参数和最终输出。
```

这样可以避免：

- 产品变形
- 接口数量错误
- 线缆颜色错误
- 探头比例错误
- 产品文字乱码
- 结构被AI随机修改

## 七、第六阶段：ComfyUI批量生成

ComfyUI主要放在“产品一致性与批量场景生成”环节，而不是策划环节。

## ComfyUI工作流结构

```Plain
产品参考图输入
↓
自动去背景或遮罩
↓
产品特征控制
↓
场景提示词读取
↓
批量种子生成
↓
ControlNet / IP-Adapter控制
↓
局部重绘
↓
高清放大
↓
自动保存
```

## 每一个图片任务批量生成

例如每张图片先生成：

```Plain
4个构图版本
×
2个光线版本
×
2个场景版本
=
16张候选图
```

AI或人工从中选择最符合要求的一张，再进入精修。

不是一次生成100张最终图，而是：

> **批量生成候选 → 筛选 → 精修 → 输出。**

# 八、第七阶段：自动自查系统

每张图片生成后，应调用对应的检查规则。

## 产品检查

```Plain
产品型号是否正确
产品数量是否正确
产品比例是否正确
线缆数量是否正确
线芯颜色是否正确
连接器是否正确
探头结构是否正确
产品是否出现变形
是否混入其他产品
```

## 场景检查

```Plain
产品安装位置是否合理
传感器是否应安装在设备内部
探头是否错误悬浮
线缆是否自然
场景是否符合产品用途
设备与产品尺寸关系是否合理
```

## 设计检查

```Plain
主标题是否足够突出
同级字体是否统一
最小文字是否清晰
产品是否被文案遮挡
画面是否过空
产品是否过于杂乱
颜色是否符合品牌规范
模块之间是否有明显层级
```

## 文案检查

```Plain
型号是否正确
参数是否来自产品资料
单位是否正确
英文大小写是否统一
是否出现乱码
是否擅自增加功能
是否把定制项写成固定参数
```

# 九、第八阶段：PS自动化处理

最终商用图仍然建议进入PS。

可以用 Codex 编写 JSX 或 UXP 脚本完成批量操作。

## 可以自动化的内容

1. 批量打开生成图
2. 批量替换产品智能对象
3. 批量替换主标题
4. 批量替换副标题
5. 批量导入参数
6. 批量统一字体和字号
7. 批量添加Logo
8. 批量检查画布尺寸
9. 批量导出JPG、PNG、WebP
10. 批量生成缩略图
11. 批量切片详情页
12. 批量按照规则命名

## PSD模板结构

```Plain
01_背景
02_场景
03_产品主体
04_产品阴影
05_光效
06_主标题
07_副标题
08_卖点标签
09_参数模块
10_品牌Logo
11_页脚
12_辅助注释
```

所有经常变化的内容都做成：

- 智能对象
- 文本变量
- 图层组
- 可替换图片槽位

# 十、第九阶段：批量命名和导出

建议统一命名：

```Plain
品牌_型号_图片类型_序号_语言_尺寸_版本
```

例如：

```Plain
GAIMC_GTS200_MainImage_01_EN_1200x1200_V01.jpg
GAIMC_GTS200_Detail_03_EN_1200x1600_V02.jpg
GAIMC_GTS200_Application_01_EN_1920x1080_V01.jpg
```

项目输出结构：

```Plain
10_Final
├─ Main_Image
├─ Detail_Page
├─ Application
├─ Structure
├─ Installation
├─ Source_PSD
├─ WebP
├─ JPG
└─ Thumbnail
```

# 十一、工具之间的正确分工


|  |  |
| --------- | -------------------------- |
| **工具** | **主要任务** |
| GPT | 资料分析、产品真值档案、图片策划、提示词、自查 |
| 本地策划工具 | 管理资料、变量、图片任务、提示词和版本 |

# 十二、你目前最适合的落地顺序

不要一开始就搭建复杂的全自动系统。

## V1：人工主导

```Plain
上传资料
→ GPT建立真值档案
→ GPT输出策划与提示词
→ AI生成图片
→ PS人工精修
```

先把流程标准跑通。

## V2：半自动化

```Plain
本地工具读取产品资料
→ 自动生成真值档案
→ 自动生成图片任务
→ 自动生成提示词
→ 批量提交生成
→ 人工筛选
→ PS模板自动替换
```

这是现阶段最值得做的版本。

## V3：高级自动化

```Plain
项目资料自动识别
→ Agent分配任务
→ ComfyUI批量执行
→ AI视觉检查
→ 自动进入PS模板
→ 自动排版
→ 自动导出
→ 自动归档
```

这一阶段才需要深入研究 ComfyUI、API、Agent 和 n8n。

# 十三、建议先做的最小可用系统

以你正在做的 **GTS200** 为测试产品，先完成以下五个模块：

```Plain
模块一：产品资料录入
模块二：产品真值档案
模块三：图片任务清单
模块四：提示词批量生成
模块五：图片审核清单
```

第一版暂时不接复杂后端，也不强行实现“一键出图”。

先建立：

> **React + Vite + TypeScript + Tailwind 的本地AI产品图工作流管理工具。**

页面采用你熟悉的形式：

```Plain
左侧：产品资料与项目设置
中间：图片任务列表
右侧：提示词、检查规则与图片预览
```

最终形成的不是一个普通提示词生成器，而是：

> **工业产品AI视觉生产管理系统。**

这套系统真正能够长期复用的核心，不是某一条提示词，而是：

**产品真值档案、图片任务模板、变量提示词系统、自查规则和PS交付模板。**
